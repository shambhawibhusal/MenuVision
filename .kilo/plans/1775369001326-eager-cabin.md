# MenuVision - Viva Questions Only

## Possible Viva Questions & Suggested Answers

### 1. What is the purpose of the menuDataset service?
**Answer:** Acts as a caching layer storing scanned menu items in Firestore. Checks if dish exists before adding new ones to improve data consistency.

### 2. How does the recommendation algorithm work?
**Answer:** Hybrid approach: 1) User's liked dishes first 2) Globally popular similar dishes 3) Preference-matching dishes. Uses Jaccard similarity on tags (ingredients, category, cuisine).

### 3. Why use both Firebase Auth and Firestore?
**Answer:** Firebase Auth handles authentication; Firestore stores user data (favorites, history, food profile) for persistent data across sessions.

### 4. Purpose of the onboarding screen?
**Answer:** Collects dietary preferences (vegetarian/vegan/gluten-free) and allergens - crucial for recommendation engine filtering.

### 5. How do you handle price normalization?
**Answer:** Detects currency symbols ($, €, £, ₹, etc.) and converts to Nepalese Rupees (NPR) using predefined exchange rates.

### 6. What is the Haversine formula used for?
**Answer:** Calculates great-circle distance between two points for filtering dishes within 2km radius of user.

### 7. How does the chat feature work?
**Answer:** Sends user messages to backend API and displays AI-generated responses about menu items, ingredients, or dietary info.

### 8. Purpose of the debounce hook?
**Answer:** Delays search execution until user stops typing for 250ms, preventing excessive API calls during real-time search.

### 9. How do you handle image processing before API calls?
**Answer:** Resizes to max 1200px, maintains aspect ratio, compresses to JPEG at 80% quality for backend API compliance.

### 10. Difference between ScannedItem and Dish interfaces?
**Answer:** ScannedItem is for newly scanned items (temporary); Dish extends it with id, place, cuisine, tags for database items.

### 11. How does the geolocation feature work?
**Answer:** Uses browser Geolocation API to get coordinates, then Nominatim API for reverse geocoding to get city/address.

### 12. What hard filters are applied in recommendations?
**Answer:** Vegetarian, vegan, gluten-free preferences and allergen exclusions - dishes not matching these are completely filtered out.

### 13. How is scan count useful in the dataset?
**Answer:** Tracks how many times a dish has been scanned - can be used to identify popular dishes or improve dataset quality.

### 14. How do you merge extracted data with dataset data?
**Answer:** Prefers dataset data for most fields but always uses scanned price, keeping extracted data as fallback for missing fields.

### 15. What is Jaccard similarity?
**Answer:** A metric for set similarity - intersection divided by union. Used to compare dish tags for recommendation scoring.
